# Build a Professional Architecture Business Website

Create a modern, professional, responsive, one-page website for an existing architecture business.

Before writing any code, inspect the existing project folder, understand its structure, identify the technology stack, and locate the business's existing logo, name, images, fonts, and other brand assets. Reuse them wherever possible. Do not invent branding or overwrite existing files unnecessarily.

## 1. Design and Theme

Use a clean, premium architectural aesthetic with these colors:

- Warm white: `#FAFAF5`
- Light orange: `#F4B183`
- Forest green: `#285943`
- Sage green: `#DCE8DC`
- Charcoal: `#292D29`

The website should feel sophisticated, spacious, minimal, and trustworthy, reflecting a professional architecture studio.

Use strong typography, balanced spacing, clean layouts, and high-quality architectural imagery where genuine assets are available. Avoid unnecessary decoration.

## 2. Website Sections

### Navigation Bar
- Display the existing business logo and name.
- Include links that navigate to the relevant sections of the page.
- Add a clear contact button.
- Make the navigation responsive on mobile devices.

### Hero Section
- Create a visually engaging introduction to the architecture business.
- Include a concise headline, supporting description, and clear call-to-action buttons.
- Use existing architectural photography or project imagery if available.
- Do not invent business claims, awards, experience, or achievements.
- Avoid generic AI-generated marketing language.

### About Us
- Introduce the architecture business, its approach, design philosophy, and services.
- Use the actual business information and existing assets when available.
- If information is missing, leave clearly identified placeholders instead of fabricating details.

### Projects / Portfolio
- Create a visually appealing grid showcasing architectural projects.
- Use existing project images and available descriptions.
- Include project titles and relevant information only when supported by the provided assets or content.
- If no project assets are available, create a clearly identifiable placeholder structure that can be populated later.
- Ensure images maintain appropriate aspect ratios and display well on different screen sizes.

### YouTube Channel
- Create a dedicated section introducing the business's YouTube channel.
- Include space for the existing channel name, description, channel link, and channel thumbnail or banner.
- Add a clear **Visit Our YouTube Channel** button that opens the official channel.
- Use placeholders for missing channel information.
- For this initial version, use a manually configurable featured video or static thumbnail if actual video information is available.
- Do not implement the YouTube Data API, dynamic video fetching, automatic latest uploads, or API integrations yet.

### Services
- Present the architecture services offered by the business in a clean, easy-to-scan layout.
- Use actual service information where available.
- Do not invent services the business does not provide.

### Contact Section
- Include space for the business's actual phone number, email address, location, and social media links where available.
- Add a clear call to action for potential clients.
- If a contact form is included, implement appropriate validation and clearly identify whether submission functionality requires a backend or external service.
- Never display fake contact information.

### Footer
- Include the existing business name and logo.
- Add relevant navigation links and available social media links.
- Include links to the Privacy Policy and Terms and Conditions pages.
- Do not create misleading legal claims or pretend that unfinished legal pages are complete.

## 3. Strict Design Rules

Avoid common AI-generated website design mistakes.

- No purple gradients.
- No unnecessary pill-shaped buttons.
- No fake reviews, testimonials, statistics, customer counts, or project metrics.
- No vague hero headlines or generic filler copy.
- No emoji used as icons.
- No em dashes in website copy.
- No excessive scroll animations or distracting transitions.
- No generic AI-looking architectural photographs presented as actual company projects.
- No animated cursor effects.
- No fake customer counters or fabricated achievements.
- No unnecessary visual effects that compromise usability.
- Do not sacrifice readability for visual appearance.

Use subtle hover effects only where they improve usability. Respect reduced-motion preferences.

## 4. Responsive Design

Build mobile-first and ensure the website works properly on:

- Mobile phones.
- Tablets.
- Laptops.
- Desktop monitors.

Requirements:

- No horizontal overflow.
- Navigation must work on mobile.
- Images must resize and crop appropriately.
- Typography must remain readable.
- Buttons and interactive elements must be easy to use on touchscreens.
- Layouts must adapt naturally rather than simply shrinking the desktop design.

## 5. Technical Requirements

- Inspect the existing project before choosing or changing technologies.
- Reuse the current framework and dependencies wherever practical.
- If the project is new, a suitable stack is Next.js, React, TypeScript, and Tailwind CSS.
- Write clean, organized, maintainable code with reusable components.
- Use semantic HTML and accessible controls.
- Optimize images and performance.
- Include appropriate page metadata, a descriptive title, and a meta description.
- Use the existing brand assets for the favicon when available.
- Structure the website so additional sections and functionality can be introduced later without rebuilding it.
- Do not add unnecessary dependencies or a backend when one is not needed.

## 6. Before Launch

Do not consider the website production-ready until the following are addressed:

- The custom domain is connected and verified.
- A proper favicon is installed.
- Any unnecessary "Made with AI" labels or branding have been removed.
- A complete and appropriate Privacy Policy page exists.
- A complete and appropriate Terms and Conditions page exists.
- All links, buttons, images, and navigation work correctly.
- The website has been tested on mobile and desktop.
- No placeholder content remains in the published version.
- Any required deployment configuration is complete.

Do not claim the website is launched or production-ready if these requirements remain incomplete.

## 7. Final Verification

After implementation:

1. Run the available build, lint, and type checks.
2. Fix errors introduced by your changes.
3. Test navigation, responsive layouts, links, and interactive elements.
4. Check for missing assets, broken images, console errors, and layout overflow.
5. Clearly report what works, what failed, and what still requires my input.

**Most importantly, make no mistakes.** Do not fabricate business information, silently remove existing functionality, or claim that something works without verifying it. If information or assets are missing, identify the gaps rather than guessing.
